## Lo realizado

### Repositorio y frontera

- Se creó este repositorio Git local en `main`, con el nombre **Nakamotito Prediction Console**.
- Los commits iniciales son `fb07bfc` (fundación) y `34425fe` (convención del grafo).
- No tiene remoto configurado: existe localmente y no se ha publicado ni empujado a GitHub.
- El código de Prediction se retiró del runtime de Trading. Trading conserva solamente su
  producto Binance/BTCUSDT; este repo posee los watchers y `prediction-state/`.

### Watchers read-only implementados

| Binario | Fuente | Salida IPC efímera | Qué observa |
|---|---|---|---|
| `prediction_watch` | Polymarket RTDS público / Chainlink | `prediction-state/prediction-watch.json` | `btc/usd` TWAP 60 s con relojes de oracle, publicación y recepción. |
| `prediction_clob_watch` | Gamma + WebSocket público CLOB de Polymarket | `prediction-state/prediction-clob-watch.json` | Ronda BTC Up/Down 5 m vigente y mejor bid/ask de Up y Down. |

Ambos procesos son independientes para que una caída del CLOB no congele el oracle. Los snapshots
se reemplazan, vencen en diez segundos y se eliminan al detenerse limpiamente. Un consumidor debe
rechazar un snapshot vencido.

Protecciones incluidas:

- Sin wallet, API key, clave privada, órdenes ni ejecución.
- Sin WAL, Parquet, DuckDB, base de datos, replay ni historial de ticks.
- Precios como texto/precisión exacta disponible, sin convertir el settlement a `f64` implícito.
- Relojes separados de observación, publicación y recepción; reconexión y último error visibles.
- Rechazo del oracle que no sea BTC/USD TWAP 60 s y descubrimiento de ronda por Gamma, sin token
  IDs fijados.

### Verificación realizada

`cargo test` pasó **4 pruebas**: dos del parseo/filtrado de TWAP y dos de Gamma/libro CLOB. Esto
verifica transformaciones deterministas; no prueba calidad de forecast, fills ni edge.

## Operación de la base actual

Desde este repositorio:

```bash
cargo test
cargo run --release --bin prediction_watch
cargo run --release --bin prediction_clob_watch
```

Los watchers se pueden iniciar en terminales separadas. La salida normal es el directorio ignorado
`prediction-state/`; ambos aceptan `--out <directorio>` para otra ubicación.

No se inician desde `nakamotito` ni se lee `state/` de Trading como parte de Prediction Console.
Una interfaz futura debe iniciar/detener ambos procesos, leer solo snapshots frescos, indicar
degradación por feed/ronda ausente o vencida y no mostrar un precio antiguo como vivo.

## Lo que falta, en orden

### Próxima entrega: consola nativa mínima propia

Construir una interfaz independiente que supervise y componga ambos watchers. Criterio de
aceptación operativo, no financiero:

- Ronda seleccionada, regla/oracle visible, cierre y tiempo restante.
- Outcomes, bid/ask, spread y frescura de cada feed.
- Relojes, salud y reconexiones; distinción clara entre `GOOD`, degradado, ausente y vencido.
- Sin órdenes, credenciales ni lectura/escritura del runtime de Trading.

Antes, fijar contrato UI/snapshot y pruebas de expiración, transición de ronda y feed caído. La
interfaz es una aplicación de este repo, no un modal o pestaña del gráfico de Trading.

### Después de la consola

1. Buffers pequeños y acotados en RAM para lag, spread, profundidad y comparaciones breves.
2. Adaptadores spot/perp multi-venue propios, etiquetados por venue, símbolo, reloj, calidad y
   semántica de precio.
3. Pruebas de salud de feed y transición de ronda con capturas sintéticas.
4. Solo entonces, diseñar `C-hat(t)`, `P(UP)` y fair value incluyendo costes, spread y latencia.
5. Proponer contrato de persistencia, retención y privacidad si hace falta reproducibilidad o
   calibración entre sesiones; nunca abrir un collector por accidente.
6. Con dataset, simulador de fills/costes y validación temporal, evaluar forecasting.

## Límites que requieren nueva autorización

- No persistir eventos, snapshots ni historial silenciosamente.
- No añadir credenciales, wallets, claves privadas ni trading real/paper.
- No importar motor Binance, `state/`, WAL, UI o estrategias de Trading.
- No afirmar que el TWAP se reproduce o anticipa exactamente.
- No generalizar tarifa, oracle o resolución entre Polymarket, Predict.fun y otros venues.
- No llamar edge a una probabilidad implícita, cotización Up/Down o feed conectado.

Persistencia, simulación con órdenes o ejecución cambian el alcance y requieren decisión
explícita, más actualización de README, arquitectura y grafo.

## Estado resumido

**Prediction Console existe como proyecto local separado y pasa cuatro pruebas unitarias.** Tiene
watchers públicos, read-only y efímeros para oracle Chainlink/RTDS y CLOB de la ronda BTC Up/Down
de Polymarket. Falta la interfaz nativa propia y luego buffers/métricas, adapters multi-venue y
validación cuantitativa. No hay persistencia, forecast, fair value, simulador, wallet ni ejecución.
El conocimiento está centralizado en Nakamotito Knowledge sin acoplar ambos productos.
